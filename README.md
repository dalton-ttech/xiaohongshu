# JEV · 多平台推广工作台

供 JEV 论文推广负责人和同事筛选账号、分配建联、记录跟进。小红书、微信公众号、抖音共用“账号池 / 建联追踪”两种视角。保留原有小红书 109 个账号与主页截图（57 个主选、52 个备选），主页资料采集于 2026-10-04。

- **账号池**：完整分组、关键词/类别/粉丝筛选、Top 10 / Top 50、GitHub 原版截图卡片布局、截图详情、参考笔记、CSV 和打印。
- **建联追踪**：默认纳入 AI / 学术 49 人、法律 AI 8 人；备选可从账号池截图详情加入。两看板共享勾选与当前状态。
- **跟进记录**：负责人、状态、首次/最近实际建联时间、下次跟进日期、备注和历史；可按今日待跟进、负责人、领域等筛选。
- **交接名单**：勾选后导出带原始主页截图、可点击主页链接的 Excel；小红书号按文本保存，粉丝为数字，已知时间为 Excel 日期。批量/单个复制输出“名称 + 制表符 + 小红书号”，每行一人。
- **访问入口**：Cloudflare Pages Functions 服务端口令验证，页面、数据和截图都受保护；12 小时签名会话，支持退出。

## 多平台功能

- **微信公众号**：18 个候选来自用户引用的“微信公众号推广建议”对话，全部标记资料 / 建联待核实，默认不加入追踪；缺失账号 ID、粉丝、文章链接等不造数。AINLP 与 AINLPer 分开，刘聪NLP / NLP工作站按别名线索记录。
- **抖音**：初始账号池为空。可添加账号、填写抖音号、主页、内容方向和代表视频；未知指标可留空。公众号同样支持新增与补充资料。
- **资料编辑**：平台账号 ID 与联系人分开；来源、核对日期、关联团队、阅读 / 播放记录单独填写。图片上传后缩小保存，单张原图上限 5 MB。当前浏览器存储满时会明确报错，不宣称保存成功。
- **跨平台工作**：切换平台保留视角和本次页面会话内的筛选 / 滚动位置；“今日待跟进”汇总各平台。手机追踪以摘要列表展示，详情展开可编辑完整字段。
- **批量操作**：分配负责人不会改写已有沟通状态；实际发出后，通过名单确认、实际日期和联系渠道批量记为待回复。首次 / 最近时间可选择仅日期，不假定午夜为发送时刻。
- **复制与 Excel**：单平台复制名称＋平台账号 ID；跨平台加平台名称；缺失 ID 明确标注待核实，不用联系人替代。Excel 按平台分工作表，保留已有图片、文本 ID、日期精度、主页和代表内容链接；未知粉丝单元格留空。
- **身份与编号**：既有小红书编号 / 勾选不变；追踪与导出标记 XHS-xxx，候选公众号使用 WX-xxx。本机新增账号生成独立随机标识，避免同事各自录入时序号碰撞；同平台重复 ID 拒绝保存，关联团队不自动合并进度。
- **备份兼容**：v2 备份携带平台资料、上传图片与跟进记录，继续接受旧 v1 小红书备份。导入先显示差异，有已有修改或账号资料覆盖时默认不勾选；选中记录后才合并，保留双方历史。旧版发布备份也不会删除已有的新平台进度。

新资料和进度仍保存在当前浏览器；没有多人实时写入后端。备份导出包含本机联系人和备注，交给维护者检查后再应用到共享版本，不将私人字段直接发布到公开仓库。

## 本地预览

需要 Node.js 20 或以上，无需安装依赖。先从 `.dev.vars.example` 创建 `.dev.vars`，设置 `ACCESS_PASSWORD` 与随机的 `ACCESS_SESSION_SECRET`（至少 32 字符），再执行：

```powershell
npm run dev
```

打开 http://127.0.0.1:8765/ 。当前电脑已配置用户指定的访问密码；`.dev.vars` 不进入 Git。不要用静态文件服务器替代此服务，否则不会执行服务端访问验证。

## 每日维护与同事协作

1. 在建联追踪中筛选未建联或今日待跟进账号，勾选名单，通过 Excel/纯文本交接。
2. 点击“记录 / 历史”分配负责人、填写实际操作时间和结果。未知时间留空；核对日期不能替代私信发送日期。
3. 编辑保存在当前浏览器的 `localStorage`。更换电脑、浏览器或网址，不会自动同步；清除浏览器数据会丢失未备份的修改。
4. 在“进度备份 / 导入”导出全部进度 JSON。另一台电脑可导入：先核对差异、勾选采用的记录，再确认导入。有已有修改的差异默认不勾选；合并保留双方历史。
5. 由维护者把最终 JSON 应用到发布数据：

```powershell
node scripts/apply-progress.mjs <进度备份.json的路径>
```

脚本校验账号编号、小红书号、状态与日期，保留上一版到被 Git 忽略的 `.local/`，仅更新 `public/assets/progress.js`。执行后尚未提交、推送或发布；按明确授权的 Git 发布流程更新网站后，同事才看到共享版本。Excel 用于执行与反馈，不会自动回写看板。

**数据边界**：本仓库仅纳入公开资料与可公开的状态，不收录私聊截图、发件账号和内部报价。JSON 备份可能包含本机备注，不要直接提交备份。网站口令只保护网站访问，不隐藏公开 GitHub 仓库中的资料；要发布私密字段，先改为合适的私有存储/仓库方案。

## Cloudflare Pages

连接本仓库，生产分支 `main`，框架 `None`，构建命令留空，输出目录 `public`，根目录留空；根目录 `functions/` 会作为 Pages Functions 部署。无需数据库或多人写入 API。

发布前必须在 Pages 的 Production 和使用中的 Preview 环境配置 Secrets：

- `ACCESS_PASSWORD`：团队访问密码，使用用户指定的值。
- `ACCESS_SESSION_SECRET`：随机的至少 32 字符密钥，不写入前端或仓库。

未配置时服务返回 503，不放行。`public/_routes.json` 覆盖全部路由，不排除静态资源；认证响应与资源使用 `private, no-store`。密码或会话密钥更换会使旧会话失效。

还需在 **Settings → Runtime → Fail open / closed** 选择 **Fail closed**，避免免费 Functions 配额耗尽时绕过验证继续提供静态资源。此项是部署平台配置，不能仅靠代码替代。参考 [Pages 中间件](https://developers.cloudflare.com/pages/functions/middleware/) 和 [路由与 Fail closed](https://developers.cloudflare.com/pages/functions/routing/)。
